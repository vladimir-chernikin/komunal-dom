# Памятка по SLA в админке АДС

Дата: 2026-04-09

## Где смотреть SLA

Открывайте карточку заявки в Django admin:

- `/admin/work_orders/workorder/<id>/change/`

SLA показывается прямо в верхней части формы заявки, в отдельном блоке:

- `SLA по заявке`
- `SLA реакции`
- `SLA локализации`
- `SLA выполнения`

Проверенные тестовые заявки с живым отсчетом:

- заявка `3-7`: [http://komunal-dom.ru/admin/work_orders/workorder/135/change/](http://komunal-dom.ru/admin/work_orders/workorder/135/change/)
- заявка `4-2`: [http://komunal-dom.ru/admin/work_orders/workorder/136/change/](http://komunal-dom.ru/admin/work_orders/workorder/136/change/)

## Как работает каждый SLA

### 1. SLA реакции

Считается:

- от момента создания заявки

Останавливается:

- при первом переводе заявки в статус `В работе`
- внутренний код статуса: `in_progress`

Результат:

- если успели в норматив: зеленая строка `SLA реакции - Успех!`
- если не успели: красная строка `SLA реакции - просрочен на ...`

### 2. SLA локализации

Считается:

- от момента создания заявки

Останавливается:

- при первом переводе в статус `Локализовано`
- или, если локализация пропущена, при переводе сразу в `Выполнена`
- внутренние коды: `localized` или `completed`

Результат:

- если успели в норматив: зеленая строка `SLA локализации - Успех!`
- если не успели: красная строка `SLA локализации - просрочен на ...`

### 3. SLA выполнения

Считается:

- от момента создания заявки

Останавливается:

- при первом переводе заявки в статус `Выполнена`
- внутренний код статуса: `completed`

Результат:

- если успели в норматив: зеленая строка `SLA выполнения - Успех!`
- если не успели: красная строка `SLA выполнения - просрочен на ...`

## Текущая статусная логика

Штатная цепочка:

1. `Новая`
2. `Назначен ответственный`
3. `В работе`
4. `Локализовано`
5. `Выполнена`
6. `Закрыта`

Связка со SLA:

1. `В работе` останавливает `SLA реакции`
2. `Локализовано` останавливает `SLA локализации`
3. `Выполнена` останавливает `SLA выполнения`

## Что важно помнить

- старые исторические заявки могут уже показывать просрочку, если они были созданы раньше, чем включили новую SLA-схему;
- для новых заявок SLA считается штатно;
- номер заявки теперь показывается в формате `{company_id}-{номер внутри компании}`.

Примеры:

- `3-5`
- `3-6`
- `4-1`
- `3-7`
- `4-2`
