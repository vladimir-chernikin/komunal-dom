# Инвентаризация API и служб: А -> Б

## Главный принцип переключения

Asterisk меняет только базовый адрес с Коммуналки А на
`https://aspect.komunal-dom.ru`; совместимый путь `/chat/api/external/`
сохраняется. До приёмки диалогового цикла этот путь Б отвечает 503 и полем
`ready_for_traffic=false`, поэтому технически живой, но незавершённый сервис
не примет звонки молча.

## API А и решение для Б

| Назначение в А | Текущий путь А | Путь/статус Б |
|---|---|---|
| диалог Asterisk/внешнего канала | `/chat/api/external/` | тот же путь; сначала безопасный 503, затем совместимый контракт |
| загрузка записи звонка | `/api/asterisk/call-recordings/` | `/api/asterisk/call-recordings/`, отдельное хранилище Б |
| MAX webhook | `/chat/api/max/webhook/` | создаётся позже с отдельным токеном Б |
| MAX notifier webhook | `/chat/api/max/notifier-webhook/` | создаётся позже с отдельным токеном Б |
| web-чат, история и производительность | `/chat/api/send/`, history/dialog/performance | отдельные `/api/v1/dialogs/*` Б |
| MAX WebApp | `/api/max-webapp/*` | отдельный модуль Б после согласования интерфейса |
| заявки | `/work_orders/*` | `/api/v1/requests/*` |
| записи Asterisk в админке | `/admin-uk/asterisk/recordings/*` | `/api/v1/debug/call-recordings/*` + React-интерфейс |

## Службы Linux

В А работают `gunicorn-komunal-dom.service`, `enhanced-aspect-bot.service` и
`komunal-ai-tools.service`, а также технические таймеры. Б не использует эти
имена и не зависит от их перезапуска.

| Служба Б | Назначение | Текущее состояние |
|---|---|---|
| `kom-dom-b-api.service` | FastAPI, `/health`, `/ready`, будущий диалог | создаётся сейчас |
| `kom-dom-b-worker.service` | будущие импорты/векторизация/долгие задачи | не создаётся до появления реальной очереди задач |
| `kom-dom-b-retention.service` + timer | очистка диагностических журналов Б | добавить после применения схемы |

Один API-процесс сейчас проще трёх пустых служб. Новая служба появляется только
вместе с работой, которую нельзя безопасно выполнить в API или системном
таймере.

## Изоляция

- порт Б `127.0.0.1:8100`, порт А не меняется;
- systemd-имена Б имеют префикс `kom-dom-b-`;
- Redis-ключи Б имеют префикс `kom_dom_b:`;
- логи Б пишутся через собственную службу и будущие таблицы Б;
- переключение Asterisk не выполняется в рамках подготовки проекта.
