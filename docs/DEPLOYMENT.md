# Развёртывание Kom_Dom_B

## Изолированные ресурсы

| Ресурс | Значение |
|---|---|
| локальная папка | `C:\codex\Kom_Dom_B` |
| production-папка | `/var/www/Kom_Dom_B` |
| домен | `aspect.komunal-dom.ru` |
| БД / владелец | `komunal_dom_b` / `komunal_b_app` |
| API | `127.0.0.1:8100` |
| systemd | `kom-dom-b-api.service` |
| Git-ветка | `kom-dom-b` |
| Redis | префикс `kom_dom_b:` |

## Переменные среды

Оригинал `.env` А копируется только как закрытый источник для переноса нужных
интеграционных параметров. Рабочий `.env` Б имеет собственные `APP_SECRET`,
`DATABASE_URL`, `PUBLIC_BASE_URL` и `EXTERNAL_API_TOKEN`. Канальные токены Б
остаются пустыми, `CHANNELS_ENABLED=false`, пока не выданы отдельные учётные
данные и не согласовано переключение.

Права рабочего файла: `root:www-data`, `0600` или `0640`. Значения секретов не
попадают в Git, документацию, журналы или вывод команд.

## Безопасный порядок запуска

1. Создать виртуальную среду Python внутри `/var/www/Kom_Dom_B/venv`.
2. Установить backend из `backend/`.
3. Запустить `kom-dom-b-api.service` только на `127.0.0.1:8100`.
4. Проверить `/health`: процесс жив.
5. Проверить `/ready`: конфигурация безопасна, каналы выключены.
6. Подключить Nginx для `aspect.komunal-dom.ru` и получить TLS-сертификат.
7. Убедиться, что `/chat/api/external/` возвращает 503 до реализации графа.
8. Схему БД применить отдельным согласованным действием.

## Откат технического контура

Остановить и отключить `kom-dom-b-api.service`, вернуть резервную копию Nginx,
проверить конфигурацию `nginx -t` и перезагрузить Nginx. Коммуналка А и Asterisk
при этом не меняются.
