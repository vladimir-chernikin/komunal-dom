# Данные для переноса из А в Б

## Выполненный этап

`0001_request_types` перенёс только справочник «ТипОбращения»:

- источник: `public.ref_service_types` production А, read-only выборка;
- приёмник: `public.request_types` production Б;
- подтверждено: ID 1 — «Инцидент», ID 2 — «Запрос»;
- проверены повторный `up` и `down` внутри транзакции с откатом;
- другие справочники и `schema_v0.sql` не применялись.

## Переносятся как рабочие данные

1. Компании/УК: название, юридические/внешние ключи, активность, иерархия.
2. Объекты: принадлежность компании, адрес, ФИАС-идентификатор, внешний ключ,
   часовой пояс и активность.
3. Категории услуг: название, описание для ИИ, признак по умолчанию и
   активность.
4. Услуги: категория, название, тип, локализация, маршрут, описание для
   человека и ИИ, внутренний/внешний признак и активность.
5. Связи объект–услуга и периоды действия.
6. Контакты: имя, телефон, email, связь с компанией/объектом.
7. Идентификаторы MAX, Telegram, телефона и других каналов.
8. Учётные записи: логин, отображаемое имя, активность. Пароль переносится
   только если его хэш совместим и безопасен; иначе выдаётся одноразовая смена.
9. Роли пользователей и области доступа к компаниям.
10. Статусы обращений и реально используемые правила работы.
11. Открытые обращения, необходимые для непрерывной работы; закрытая история —
    отдельной согласованной глубиной.
12. Файлы переносимых обращений. Связи старых заявок отдельно не переносятся,
    пока не утверждён соответствующий бизнес-сценарий.
13. Активные шаблоны GigaChat и их используемые версии.
14. Нужные константы, но не секреты среды.

## Не переносятся как рабочее состояние

Старые LangGraph-контрольные таблицы, кэши, блокировки и внутренние поля А не
становятся состоянием Б. Для сравнения можно импортировать выбранные диалоги в
отдельный тестовый набор, не связывая их со свежими production-сессиями.

## Порядок

`data_import_runs` фиксирует запуск. Импорт читает строку А, преобразует во
временную структуру, проверяет обязательные ссылки и пишет запись Б. Ошибка
попадает в `data_import_errors`; строка не исчезает молча. После каждого типа
сверяются количество, внешние ключи и выборка карточек в интерфейсе.

Секреты не являются данными переноса. Они копируются отдельно в закрытый `.env`
Б, каналы остаются выключенными до согласованной маршрутизации.
