# Развёртывание Kom_Dom_B на новом сервере

Этот файл — исполняемый журнал развёртывания. Любое изменение production-пути,
службы, переменной среды, БД, Nginx, Telegram или порядка миграций обновляет
его в том же коммите.

## Целевая раскладка

| Ресурс | Значение |
|---|---|
| корень приложения | `/Kom_Dom_B` |
| домен | `aspect.komunal-dom.ru` |
| API | `127.0.0.1:8100` |
| служба | `kom-dom-b-api.service` |
| база / пользователь | `komunal_dom_b` / `komunal_b_app` |
| Git-ветка | `kom-dom-b` |
| Redis-префикс | `kom_dom_b:` |
| медиа | `/Kom_Dom_B/media` |

## Подготовка чистого сервера

1. Установить PostgreSQL 16, расширение `pgvector`, Nginx, Python 3.12,
   `venv`, Git и Certbot.
2. Создать системного пользователя приложения без интерактивного входа.
3. Клонировать только ветку `kom-dom-b` в `/Kom_Dom_B`.
4. Создать виртуальную среду. На новом сервере предпочтителен внешний путь
   `/opt/kom-dom-b/venv`, чтобы исполняемая среда не смешивалась с Git; сейчас
   этот каталог не создаётся.
5. Создать отдельные БД и роль. Администратор PostgreSQL один раз выполняет
   `CREATE EXTENSION vector` в БД проекта; прикладная роль не получает право
   установки расширений. Пароль поместить только в `/Kom_Dom_B/.env` с
   правами `root:www-data 0640`.
6. Установить проект из корневого `pyproject.toml`.
7. Выполнять SQL-файлы `db/migrations` строго по номеру. Перед и после каждой
   миграции записывать число строк и контрольные значения. `0001` создаёт
   только `request_types`; `db/design/schema_v0.sql` отдельно не применяется.
8. Установить `admin/ops/systemd/kom-dom-b-api.service`, выполнить
   `systemctl daemon-reload`, включить и запустить службу.
9. Установить Nginx-конфигурацию из `admin/ops/nginx`, проверить `nginx -t`,
   получить TLS-сертификат.
10. Проверить локально и публично `/health`, `/ready`, `/`, а также ожидаемый
    отказ незавершённого `/chat/api/external/`.
11. Telegram переводить только после проверки `/tg/webhook` с закрытым
    заголовком: остановить старый polling-процесс А, вызвать `setWebhook`,
    проверить `getWebhookInfo`, отправить одно реальное сообщение.

## Резервный путь

Перед обновлением сохраняются:

- архив текущего Git checkout без `.env`, `venv` и `media`;
- отдельная закрытая копия `.env`;
- дамп схемы/данных БД;
- действующие unit-файлы systemd и Nginx;
- текущий URL Telegram webhook и состояние старой службы.

Возврат Telegram: удалить webhook, запустить старый polling-процесс А и
проверить `getWebhookInfo`. Возврат API: восстановить предыдущий архив/коммит,
unit-файл, выполнить `daemon-reload` и перезапустить службу.

## Папки, которые сейчас не создаются

- `docker/` — нужен только после решения действительно контейнеризовать
  приложение; сейчас systemd проще.
- `venv/` в Git-структуре — это среда сервера, а не исходный код.
- `logs/` — журнал ведёт journald; второй каталог логов создаст дубли.
- `tmp/` — временные файлы используют системный `/tmp`.
- `backups/` внутри проекта — резервные копии должны жить вне checkout и
  выгружаться во внешнее хранилище.
