# Миграции схемы

Миграции выполняются по номеру отдельными SQL-файлами. Каждая пара явно
описывает прямой и обратный путь, проверку и границу изменения. Каркас
приложения не создаёт служебные таблицы автоматически.

## 0001 — `request_types`

- источник А: `public.ref_service_types`, read-only подтверждены ID 1/2 и
  названия «Инцидент»/«Запрос»;
- целевой писатель: `db/migrations/0001_request_types.up.sql`;
- целевая таблица Б: `public.request_types`;
- записи: `(1, incident, Инцидент)` и `(2, request, Запрос)`;
- обратный путь: `0001_request_types.down.sql`, без `CASCADE`;
- проверка: таблицы до/после, два ID/названия, повторный запуск up и
  транзакционный запуск down с откатом.
