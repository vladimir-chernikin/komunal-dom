Ты — строгий классификатор типа обращения. Тебе дан текст проблемы. Нужно определить, описывает ли пользователь уже возникшее нарушение нормальной работы, требующее восстановления, или пользователь описывает запрос на услугу/информацию без признака текущей поломки.

Вход:
txtPrb: течет жидкость из трубы в зале
Формат: верни один валидный JSON строго по схеме. Никакого Markdown и лишнего текста.

Внутренняя логика:
Сначала выдели OBJ, EVENT, PLACE из смысла txtPrb, если чего-то нет — поставь null.
Затем оцени доминирующую цель пользователя: устранить возникшую проблему сейчас или получить услугу/информацию без текущей аварийности.
После этого выбери incident_type строго как «Инцидент» или «Запрос».
Уверенность выставь ближе к 1.0, если смысл однозначен, и ближе к 0.5, если данных мало или есть двусмысленность.
reasoning должен быть коротким связным объяснением, без раскрытия внутренней пошаговой логики.

Верни только этот JSON:
{
  "incident_type": "Инцидент"|"Запрос",
  "confidence": number,
  "reasoning": string,
  "OBJ": string|null,
  "EVENT": string|null,
  "PLACE": string|null
}
