# HOOK: UI Change Post-Check

**Назначение:** Проверка после UI-изменений в Django проекте.

**Приоритет:** Высокий (срабатывает после любых изменений templates/views/forms/admin).

---

## КОГДА СРАБАТЫВАЕТ

Hook срабатывает ПОСЛЕ завершения изменений:

### После изменения templates:
- Создание/редактирование `.html` файлов
- Изменение Django templates
- Изменение компоновки экрана

### После изменения views:
- Создание/редактирование `views.py`
- Изменение логики отображения

### После изменения forms:
- Создание/редактирование `forms.py`
- Добавление/изменение полей формы

### После изменения admin:
- Создание/редактирование `admin.py`
- Изменение fieldsets
- Изменение list_display

---

## КОГДА НЕ СРАБАТЫВАЕТ

- ❌ После изменения models.py (это DB schema, не UI)
- ❌ После изменения business logic без UI impact
- ❌ После runtime операций (gunicorn, nginx)
- ❌ После работы с git, файлами, директориями

---

## ЧТО ДЕЛАЕТ HOOK

1. **ПРОВЕРЯЕТ права доступа:**
   - Проверяет права на template файлы
   - Проверяет владельца файлов
   - Предупреждает, если права неверные

2. **ПРОВЕРЯЕТ синтаксис Python (если нужно):**
   - Проверяет синтаксис измененных `.py` файлов
   - Использует `python -m py_compile` для проверки

3. **ПРОВЕРЯЕТ Django (если возможно):**
   - Запускает `python manage.py check`
   - Проверяет на ошибки Django
   - Показывает результат

4. **ПРЕДЛАГАЕТ перезапуск gunicorn:**
   - Если менялись `.py` файлы — предлагает перезапустить
   - Если менялись `.html` файлы — предлагает перезапустить (для надежности)
   - НЕ перезапускает автоматически

5. **НЕ ЗАПРЕЩАЕТ завершение:**
   - Если проверки не прошли — предупреждает, но НЕ останавливает
   - Если пользователь хочет продолжить — позволяет

## ПРЕДОХРАНИТЕЛИ

**ЕСЛИ python manage.py check не может выполниться:**
- ⚠️ Сообщение: "Не удалось выполнить python manage.py check"
- ✅ Объяснить причину (окружение, зависимости)
- ✅ Предложить альтернативные проверки
- ❌ НЕ падать молча

**ЕСЛИ права доступа неверные:**
- ⚠️ Предупреждение: "Неверные права доступа"
- ✅ Показать текущие права
- ✅ Показать правильные права
- ✅ Предложить исправить
- ❌ НЕ исправлять автоматически

**ЕСЛИ синтаксис Python неверный:**
- ⚠️ Предупреждение: "Синтаксическая ошибка Python"
- ✅ Показать ошибку
- ✅ Предложить исправить
- ❌ НЕ останавливать работу жестко

## ТЕХНИЧЕСКИЕ ПРОВЕРКИ

**Проверка прав доступа:**
```bash
ls -la /var/www/komunal-dom_ru/work_orders/templates/work_orders/*.html
```

**Ожидаемые права:**
```bash
-rw-r--r-- 1 olga www-data ... template.html
```

**Проверка синтаксиса Python:**
```bash
python -m py_compile /var/www/komunal-dom_ru/work_orders/views.py
```

**Проверка Django:**
```bash
cd /var/www/komunal-dom_ru && python manage.py check
```

**Перезапуск gunicorn (если нужно):**
```bash
systemctl restart gunicorn-komunal-dom
systemctl status gunicorn-komunal-dom
```

## БЕЗОПАСНЫЕ ПРОВЕРКИ БЕЗ PYTHON MANAGE

**ЕСЛИ python manage.py check НЕ доступен:**

1. **Проверка синтаксиса Python:**
   ```bash
   python -m py_compile views.py
   ```

2. **Проверка импортов (базовая):**
   ```bash
   python -c "import work_orders.views"
   ```

3. **Проверка прав доступа:**
   ```bash
   ls -la template.html
   ```

4. **Проверка доступности страницы (если gunicorn запущен):**
   ```bash
   curl -I http://localhost:8000/work_orders/request/1/
   ```
