**Назначение:** Роутер по базе знаний проекта. Используйте этот файл, чтобы найти нужную информацию.

## СОДЕРЖАНИЕ БАЗЫ ЗНАНИЙ

### [DB_ACCESS.md](DB_ACCESS.md) - Доступ к базе данных

**Назначение:** Безопасные паттерны доступа к PostgreSQL, protocol подключения к БД.

**Открыть когда:**
- Нужно выполнить SQL-запрос через `psql`
- Возникает ошибка `password authentication failed`
- Нужен прямой доступ к PostgreSQL (не через Django ORM)
- Нужно проверить подключение к БД
- Вопросы по credentials, connection, auth

**Обновить когда:**
- Изменился источник конфигурации (другой .env, другой механизм)
- Добавился новый способ загрузки credentials
- Изменился runtime (добавились systemd env files)

**Факты:**
- PostgreSQL 16, aspect_objects_db, aspect_db
- Source of truth: `.env` файл в корне проекта
- Django использует `python-decouple` для загрузки credentials
- Никогда не угадывать пароль из памяти или документации

**КРИТИЧЕСКИ ВАЖНО:** Это ПЕРВЫЙ файл, который нужно прочитать перед любым SQL/psql!

## КАНДИДАТЫ НА БУДУЩИЕ SKILLS

Эти разделы повторяются 3+ раз и имеют четкие шаги → хорошие кандидаты для Skills:

### DB Operations Skill

**Когда использовать:** Все задачи с SQL запросами, миграциями, пользователями

**Включает:**
- SQL запросы к БД
- Миграции Django (makemigrations, migrate)
- Создание пользователей PostgreSQL
- Работа с credentials и подключениями к БД

**Команды:**
```bash
# СНАЧАЛА прочитать DB_ACCESS.md для безопасных паттернов!
cd /var/www/komunal-dom_ru
export $(cat .env | grep -v '^#' | xargs)
./manage.py makemigrations
./manage.py migrate
PGPASSWORD="$DB_PASSWORD" psql -h "$DB_HOST" -U "$DB_USER" -d "$DB_NAME" -c "..."
```

### Diagnostics Skill

**Когда использовать:** Диагностика проблем, трассировка диалогов

**Включает:**
- TraceReportService
- DialogTraceService
- Генерация отчетов
- Анализ диалогов

**Команды:**
```bash
python dialog_trace_service.py --session-id web_123_abc
python trace_report_service.py telegram_123456
```

### Deploy/Runtime Skill

**Когда использовать:** Управление сервисами, deploy, restart

**Включает:**
- systemctl команды
- nginx reload/restart
- gunicorn restart
- Проверка статусов сервисов

**Команды:**
```bash
systemctl restart gunicorn-komunal-dom
systemctl reload nginx
systemctl status gunicorn-komunal-dom nginx
```

## СЕКРЕТЫ И ЧУВСТВИТЕЛЬНЫЕ ДАННЫЕ

**КРИТИЧЕСКИ ВАЖНО:** Реальные секреты НЕ хранятся в MD_DB!

- ✅ **Где лежат:** В файле `.env` (в корне проекта)
- ✅ **Что там:** DB_PASSWORD, API ключи, SECRET_KEY
- ❌ **Что НЕ делать:** Не коммитить .env в git!
- ❌ **Что НЕ делать:** Не писать реальные пароли в документацию!

**Placeholders в документации:**
- `[ПАРОЛЬ БД]` - пароль PostgreSQL (смотри в .env)
- `[ПОЛЬЗОВАТЕЛЬ АДМИНКИ]` - логин админки Django
- `[ПАРОЛЬ АДМИНКИ]` - пароль админки Django
- `[API KEY]` - API ключи внешних сервисов
