## 1. СУТЬ ЛЕКЦИЙ (Важные моменты для промпта)

### 1.1. Воронка продаж (Sales Funnel)

**7 этапов:**
1. **Привлечение внимания** - первый контакт
2. **Квалификация** - понимание потребности
3. **Выявление нужд** - уточнение деталей
4. **Презентация решения** - предложение услуги
5. **Работа с возражениями** - до 4 итераций
7. **Закрытие сделки** - создание заявки/оплата

**Применение к MainAgent:**
- Не продавать, а **выявлять потребность**
- Уточнять детали постепенно (1 вопрос за раз)
- Предлагать решение только после полного понимания

### 1.2. Multi-Agent архитектура

**Принцип:** Router + специализированные агенты

```
Router → анализирует запрос → направляет подходящему агенту
```

**Агенты:**
- **NeedsExtractor** - извлечение потребностей
- **ObjectionHandler** - обработка возражений (до 4 итераций)
- **CoursePresenter** - презентация услуг
- **Finalizer** - закрытие (создание заявки)

**Применение к MainAgent:**
- **CriticalHandlerAgent** - критические ситуации (безопасность)
- **ServiceClassifierAgent** - классификация услуг
- **GeneralInquiryAgent** - общие вопросы

### 1.3. RAG (Retrieval Augmented Generation)

**Принцип:** LLM + база знаний = умные ответы

**Компоненты:**
1. **FAISS** - векторный поиск (k=3-6 фрагментов)
2. **Embeddings** - векторизация текста (OpenAI/Yandex)
3. **LLM** - генерация ответа с найденным контекстом

**Применение к MainAgent:**
- База знаний: правила проживания, тарифы, ЖКХ нормы
- Поиск: по истории заявок, регламентам
- Ответ: с учетом найденной информации

### 1.4. Диалоговое суммирование (Dialog Summarization)

**Принцип:** После каждого сообщения - обновление summary

**Формат:**
```python
summary = {
    "entities": {"location": "кухня", "problem": "течет кран"},
    "new_info": "Пользователь уточнил: кран на кухне",
    "next_step": "Создать заявку"
}
```

**Применение к MainAgent:**
- **txtPrb** - накопленное описание проблемы
- **История** - что спрашивалось, что отвечено
- **Следующий шаг** - что делать дальше

### 1.5. Работа с возражениями (Objection Handling)

**Принцип:** До 4 итераций уточнения

**Итерации:**
1. Уточняющий вопрос
2. Альтернатива
3. Компромисс
4. Передача оператору

**Применение к MainAgent:**
- Максимум **3-4 вопроса** до создания заявки
- После 4-х итераций → **передача оператору**

### 1.6. Комплементарный стиль

**Принцип:** Подтверждение фактов + вопрос

**Пример:**
```
❌ "Где это произошло?"
✅ "Вижу, что у вас течет, но вы не уточнили место. Где именно?"
```

**Применение к MainAgent:**
- При отказе от услуги → **сначала подтверждение, потом вопрос**
- "Вижу, что [факт]. Но [возражение]. [новый вопрос]"

### 1.7. Temperature (Температура LLM)

**Принцип:** Разная температура для разных задач

| Задача | Temperature | Почему |
|---------|-------------|---------|
| **Анализ/классификация** | 0.15 | Строгость, детерминизм |
| **Генерация вопросов** | 0.3-0.5 | Творчество, вариативность |
| **Создание заявки** | 0.15 | Точность, формат |

**Применение к MainAgent:**
- Router: 0.15 (анализ типа запроса)
- ServiceClassifier: 0.3 (генерация вопросов)
- CriticalHandler: 0.15 (безопасность важна)

### 1.8. Entity Extraction (Извлечение сущностей)

**Принцип:** NLP для структурирования данных

**Сущности:**
- **needs** - потребности клиента
- **benefits** - выгоды, которые ищет клиент
- **objections** - возражения
- **location** - место проблемы
- **urgency** - срочность

**Применение к MainAgent:**
```python
entities = {
    "object": "кран",
    "event": "течет",
    "place": "кухня",
    "source": "соседей сверху",
    "urgency": "нормальная"
}
```

### 1.9. Психологические триггеры

**Принцип:** Эмоциональный интеллект

**Триггеры:**
- **Cool goal** (крутая цель) - мотивация
- **Метафоры** - понятные образы
- **Социальное доказательство** - "у других тоже работает"

**Применение к MainAgent:**
- НЕ ИСПОЛЬЗОВАТЬ (это B2C продажи)
- Использовать только: **эмпатия**, **понимание проблемы**, **готовность помочь**

## 3. ВАЖНЫЕ МОМЕНТЫ ДЛЯ ПРОМПТА

### 3.1. Обязательные правила

1. **Один вопрос за раз** - запрещены двойные вопросы
2. **Только открытые вопросы** - "Где/Что/Как/Почему", запрещены "да/нет"
3. **Не повторяться** - учитывать историю диалога
4. **Максимум 10 слов** - краткость вопроса
5. **Без эмодзи** - только текст

### 3.2. Приоритет безопасности

**Критические ситуации:**
- Угроза жизни: пожар, газ, обрушение, электроток
- Угроза здоровью: плесень, травмоопасность
- Угроза имуществу: затопление, прорыв канализации

**Действие:**
1. Определить уровень угрозы
2. 1-2 вопроса (максимум)
3. Создать заявку с ПРИОРИТЕТОМ "ВЫСОКИЙ"
4. Немедленная эскалация оператору

### 3.3. Параметры услуги

**1. Локализация (Где?)**
- Индивидуальное: квартира, балкон, лоджия, ванная, кухня, спальня, туалет
- Общедомовое: подъезд, лифт, подвал, чердак, крыша, фасад, двор, парковка

**2. Тип (Что случилось?)**
- Инцидент: прорыв, поломка, засор, не работает, течет, застрял
- Плановые работы: ремонт, замена, установка, обслуживание

**3. Объект (Что именно?)**
- Труба, кран, батарея, розетка, выключатель, окно, дверь, лифт, мусоропровод

### 3.4. Алгоритм работы

1. **Проверка критической ситуации** → при угрозе: эскалация
2. **Извлечение информации** → OBJ, EVENT, PLACE, SOURCE
3. **Определение услуги** → поиск по хэштегам
4. **Проверка полноты** → чего не хватает: спросить
5. **Создание заявки** → вся информация: JSON + подтверждение

### 3.5. Temperature

- **Анализ и маршрутизация:** 0.15 (строгий)
- **Генерация вопросов:** 0.3 (творческий)
- **Создание заявки:** 0.15 (строгий)

### 3.6. Исторический контекст

**Учитывать:**
- Что уже спрашивалось
- Что пользователь уже сообщил
- Какие фильтры уже установлены

**НЕ ПОВТОРЯТЬ вопросы на уже известные факты!**

### 3.7. Комплементарный стиль (при отказе)

**Формула:**
```
"Вижу, что [факт]. Но [возражение/отказ]. [уточняющий вопрос]"
```

**Пример:**
```
"Вижу, что у вас течет, но вы не считаете это прорывом канализации. Где именно это происходит?"
```

## 4. СУБ-АГЕНТЫ (Кратко)

### 4.1. CriticalHandlerAgent
**Что делает:** Обрабатывает критические ситуации (пожар, газ, затопление)
**Сколько вопросов:** Максимум 1-2
**Приоритет:** Высокий, немедленная эскалация

### 4.2. ServiceClassifierAgent
**Что делает:** Классифицирует услуги по 13 категориям
**Сколько вопросов:** До 3-4 (по алгоритму)
**Использует:** TagSearch, VectorSearch, FilterDetection

### 4.3. GeneralInquiryAgent
**Что делает:** Отвечает на общие вопросы (часы, адрес, оплата)
**Сколько вопросов:** 0 (ответ или передача оператору)
**Использует:** Типовые ответы
