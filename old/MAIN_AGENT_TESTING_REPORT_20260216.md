## 1. Цели тестирования

1. Проверить работоспособность нового универсального промта Main Agent с RAG-архитектурой
2. Проверить выполнение критических правил (безопасность, негатив, формат ответов)
3. Оценить качество ответов на типичных запросах пользователей
4. Измерить стоимость запросов к YandexGPT API
5. Выявить проблемы и недочёты промта

## 2. Описание промта

### Архитектура

**Версия v3 (corrected)** - упрощённая и исправленная версия

**Размер:** 2085 символов (по сравнению с 8547 в v2)

**Ключевые особенности:**
- RAG-подход с базой знаний и каталогом услуг
- Явные критические правила в начале промта
- Safety-check как первый шаг алгоритма
- Чёткое разделение MODE (CHAT, TRIAGE, NEGATIVE, CATALOG)
- Запрет на показ внутренних метаданных пользователю

### Переменные шаблона

```python
{
    'message_text': str,      # Текущее сообщение пользователя
    'context': str,           # История диалога
    'SERVICE_CATALOG': str,   # Каталог услуг (теги)
    'KNOWLEDGE_BASE': str     # База знаний (регламенты, инструкции)
}
```

### Критические правила

1. **ОТВЕТ ПОЛЬЗОВАТЕЛЮ** - только 1-2 предложения текста + 0/1 вопрос
2. **НИКАКИХ внутренних метаданных** в ответе (нет JSON, нет "этап воронки", нет "MODE:")
3. **Вопрос ≤ 10 слов**, только открытый (НЕ "да/нет")
4. **Без эмодзи**
5. **Safety-check ПЕРВЫМ** для газа/пожара/травмы

## 6. Проблемы и их решение

### Проблема 1: Показ внутренних метаданных (v2)

**Описание:**
Версия v2 промта (8547 символов) приводила к тому, что модель показывала пользователю внутренние метаданные:

```
Здравствуйте! Что случилось? Опишите ситуацию, пожалуйста.

**Этап воронки:** 2 (Контекст)
**txtPrb:**
{
  "summary": "Пользователь сообщает о запахе газа...",
  "stage7": 2,
  ...
}
```

**Решение:**
1. Упрощение промта с 8547 до 2085 символов
2. Добавление явного правила в начало промта:
   ```
   2. **НИКАКИХ внутренних метаданных** в ответе (нет JSON, нет "этап воронки", нет "MODE:", нет "txtPrb")
   ```
3. Добавление секции "ВАЖНО" в конце промта

**Результат:** ✅ Проблема устранена в v3

---

### Проблема 2: Несрабатывание Safety-check (v2)

**Описание:**
На запрос "Пахнет газом" модель v2 отвечала:
```
Здравствуйте! Что случилось? Опишите ситуацию, пожалуйста.
```

**Решение:**
1. Перемещение Safety-check на первое место в алгоритме
2. Добавление примеров критических ситуаций
3. Добавление примера ПРАВИЛЬНОГО ответа для газа:
   ```
   "Понял проблему с газом. Срочно покиньте квартиру и вызовите 104. Есть кто-нибудь внутри?"
   ```

**Результат:** ✅ Проблема устранена в v3

---

### Проблема 3: Двойные вопросы

**Описание:**
В некоторых сценариях модель задаёт 2 вопроса вместо 1:

```
Понял, лифт не работает. Нужна помощь? Где именно застрял лифт?
```

**Статус:** ⚠️ Минорная проблема
**Частота:** 1/8 (12.5%)
**Влияние:** Незначительное

**Рекомендация:**
Можно усилить правило "Один вопрос за сообщение" добавлением примеров с одним вопросом.

### Проблема 4: Превышение лимита слов

**Описание:**
В 1 из 8 случаев длина ответа превышает 10 слов (12-13 слов).

**Статус:** ⚠️ Минорная проблема
**Частота:** 1/8 (12.5%)
**Влияние:** Незначительное (особенно для safety-ситуаций)

**Рекомендация:**
Можно оставить как есть, так как превышение незначительное и оправдано для сложных ситуаций.
