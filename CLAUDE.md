#### Ошибка 3: Изменил код, но забыл перезапустить Gunicorn (2026-03-10)

**Ошибка:** Изменил код Python, но изменения не применяются - работает старый код

**Причина:** Gunicorn кеширует Python код в памяти workers. После изменений кода нужно перезагружать workers.

**ПРАВИЛО:**
- ✅ СРАЗУ после изменений `.py` файлов: `systemctl restart gunicorn-komunal-dom`
- ✅ Проверить что gunicorn запущен: `systemctl status gunicorn-komunal-dom`
- ❌ ЗАПРЕЩЕНО: Изменять код БЕЗ перезапуска gunicorn

**Чек-лист после изменений Python кода:**
```bash
# 1. Изменить .py файл

# 2. Перезапустить gunicorn
systemctl restart gunicorn-komunal-dom

# 3. Проверить статус
systemctl status gunicorn-komunal-dom --no-pager -l | head -15

# 4. Проверить что запустился НОВЫЙ процесс (Active: active (running) since СЕЙЧАС)
```

**ВАЖНО:** Gunicorn workers кешируют код! Без restart они будут использовать СТАРЫЙ код!

**ИСКЛЮЧЕНИЕ:** Изменения `.html` шаблонов НЕ требуют перезапуска (nginx отдает их напрямую)

#### Ошибка 4: Забыл установить права на файлы после создания (2026-03-10)

**Ошибка:** Создал файлы через Write tool, но nginx/gunicorn не может их читать

**Причина:** Файлы создаются от root с правами 600, а nginx работает от www-data

**ПРАВИЛО:**
- ✅ СРАЗУ после Write tool: `chmod 644 файл` && `chown olga:www-data файл`
- ✅ Для директорий: `chmod 755 директория`
- ❌ ЗАПРЕЩЕНО: Создавать файлы БЕЗ установки прав

**Чек-лист после создания файлов:**
```bash
# 1. Проверить владельца и права
ls -la файл

# 2. Если владелец root:root или права 600 - ИСПРАВИТЬ
chmod 644 файл
chown olga:www-data файл

# 3. Для Django templates/static - обязательно!
```

**Критичные файлы:** Django templates (.html), статические файлы, миграции

#### Ошибка 6: Пытался создать пользователя PostgreSQL от имени aspect_db (2026-03-10)

**Ошибка:** `CREATE USER aspect_alex` от имени aspect_db → `permission denied`

**Причина:** У aspect_db не было права CREATEROLE

**ПРАВИЛО:**
- ✅ Создание пользователей: `sudo -u postgres psql -c "CREATE USER ..."`
- ✅ Затем выдать права: от `aspect_db`
- ❌ ЗАПРЕЩЕНО: Создавать пользователей от обычных пользователей БД

**Правильная последовательность:**
```bash
# 1. Создать пользователя (от postgres или от root с CREATEROLE)
sudo -u postgres psql -c "CREATE USER aspect_alex WITH PASSWORD '...';"

# 2. Выдать права на БД (от aspect_db)
PGPASSWORD="DB_Aspect_2025" psql -h localhost -U aspect_db -d aspect_objects_db -c "GRANT CONNECT ON DATABASE aspect_objects_db TO aspect_alex;"
```

### СТАНДАРТНЫЙ WORKFLOW:

```bash
# 1. Создаем ветку под задачу (ОДИН РАЗ)

# 4. После создания PR - запросить у пользователя разрешение на слияние
#    ИЛИ подождать подтверждения
```

### КОГДА ДЕЛАТЬ КОММИТ:

✅ **СРАЗУ ПОСЛЕ каждого изменения:**
- Изменил 1-2 файла → коммит
- Исправил баг → коммит
- Добавил функцию → коммит
- Переименовал переменную → коммит
- **ЗАВЕРШИЛ ЗАДАЧУ** → НЕМЕДЛЕННО коммит!

❌ **ЗАПРЕЩЕНО:**
- Оставлять изменения незакоммиченными "на потом"
- Делать несколько изменений перед коммитом
- Откладывать коммит "потом разберусь"
- Работать в main (кроме pull)
- **Переходить к следующей задаче БЕЗ коммита!**

## 6. ПРАВА ДОСТУПА К ФАЙЛАМ В /TMP


## 6-A. ПРАВА ДОСТУПА ДЛЯ DJANGO ФАЙЛОВ (Write tool)

### ⚠️ КРИТИЧЕСКИ ВАЖНО:

**ПРИЧИНА:** Когда Claude создает файлы через Write tool, они создаются от пользователя, который запустил процесс. Если это root - файлы будут с правами `600` и владельцем `root:root`, что делает их недоступными для gunicorn (работает от `www-data`).

**КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО:** Создавать Django templates, статические файлы, или любые файлы, которые использует веб-сервер, БЕЗ последующей установки прав.

**ОБЯЗАТЕЛЬНЫЙ КОД ПОСЛЕ Write tool:**

```bash
# Для Django шаблонов
chmod 644 /var/www/komunal-dom_ru/путь/к/файлу.html
chown olga:www-data /var/www/komunal-dom_ru/путь/к/файлу.html

# Для целых директорий
find /var/www/komunal-dom_ru/имя_приложения/templates/ -type f -name "*.html" -exec chmod 644 {} \;
chown -R olga:www-data /var/www/komunal-dom_ru/имя_приложения/templates/
```

**АВТОМАТИЧЕСКАЯ ПРОВЕРКА:** После создания файла через Write tool, ВСЕГДА выполнять:

1. Проверить владельца: `ls -la файл`
2. Если владелец `root:root` - исправить: `chown olga:www-data файл`
3. Если права `600` или `-rw-------` - исправить: `chmod 644 файл`
4. Перезапустить gunicorn: `systemctl restart gunicorn-komunal-dom`

**ОСОБЕННО ВАЖНО:** Django templates (`.html` файлы в `*/templates/`), статические файлы, миграции - ВСЕ должно быть читаемым для `www-data`!

## ВЕКТОРНЫЙ ПОИСК (VectorSearchService)

### Реализация: ✅ 2026-01-13

**Двойной векторный поиск:**
1. **По embedding тегов** (точность):
   - Загружает embedding из `ref_tags.embedding_tag` (JSONB, 256 float)
   - Вычисляет косинусное сходство
   - Порог: 0.70
   - Группирует по service_id (максимум)

2. **По embedding услуг** (полнота):
   - Загружает embedding из `services_catalog.embedding_service` (JSONB, 256 float)
   - Вычисляет косинусное сходство
   - Порог: 0.70

3. **Слияние результатов**:
   - Используется **СРЕДНЕВЗВЕШЕННОЕ**: `0.6 * tag_conf + 0.4 * service_conf`
   - Если найден только в одном → не штрафуем (confidence = найденный)
   - Сортировка по DESC, возврат TOP-10

**Формула косинусного сходства:**
```
cosine_sim = (vec1 · vec2) / (||vec1|| * ||vec2||)
где:
- vec1 · vec2 = скалярное произведение
- ||vec|| = L2 норма (длина вектора)
```

**Генерация embedding:**
- Скрипты: `generate_tag_embeddings.py`, `generate_service_embeddings.py`
- Модель: Yandex Embeddings API (`text-search-doc`)
- Размерность: 256 float
- Предобработка: NLTK stopwords (151 слово) + pymorphy2 лемматизация
- Стоимость: ~0.14 руб для всей БД (350 тегов + 68 услуг)
