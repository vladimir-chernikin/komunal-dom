## 7. ПРАВА ДОСТУПА К ФАЙЛАМ В /TMP (КРИТИЧЕСКИ ВАЖНО)

**Дата введения:** 2025-12-26

### ⚠️ ПРАВИЛО для создаваемых файлов в /tmp:

**ОБЯЗАТЕЛЬНО:** После создания файлов в `/tmp` устанавливать права на чтение для всех пользователей.

**ПРИЧИНА:**
- Веб-сервер (nginx/gunicorn) работает от пользователя `www-data`
- Django код может создавать файлы от `root` или другого пользователя
- Файлы с правами `600` (только для владельца) недоступны для веб-сервера
- Это вызывает ошибку `Permission denied` при чтении через веб-интерфейс

**ОБЯЗАТЕЛЬНЫЙ КОД после создания файла:**
```python
import os

# После создания файла
output_path.write_text(content, encoding='utf-8')
os.chmod(output_path, 0o644)  # rw-r--r--
```

**ПРИМЕР ПРАВИЛЬНОГО КОДА:**
```python
# Сохраняем отчет
output_path.write_text(report_content, encoding='utf-8')

# Устанавливаем права на чтение для всех (фикс для веб-сервера www-data)
import os
os.chmod(output_path, 0o644)  # rw-r--r--
logger.info(f"Создан файл: {output_path} (права: 644)")
```

**НЕПРАВИЛЬНЫЙ КОД:**
```python
# ❌ БЕЗ установки прав - веб-сервер не сможет прочитать!
output_path.write_text(report_content, encoding='utf-8')
```

**КАКИЕ ФАЙЛЫ ТРЕБУЮТ ПРАВИЛЬ 644:**
- Отчеты трассировки: `_tras_diag_*.md`
- Файлы отчетов: `*_REPORT_*.md`, `*_ANALYSIS_*.md`
- Любые файлы в `/tmp` которые читаются через веб-интерфейс

**ПРОВЕРКА:**
```bash
# Проверить права на файлы в /tmp
ls -la /tmp/*.md

# Должны быть: -rw-r--r-- (644)
# НЕ должно быть: -rw------- (600)
```

## DialogTraceService - Микросервис трассировки (追踪服务 - zhuīzōng fúwù)

**Файл:** `/var/www/komunal-dom_ru/dialog_trace_service.py`

**Назначение:**
- Выдача детальной трассировки диалога по воронке точности
- Анализ ответов всех микросервисов на каждом этапе
- Контроль промтов LLM и установленных фильтров
- Проверка памяти (context) диалога

### Запуск трассировки:

```bash
cd /var/www/komunal-dom_ru
source venv/bin/activate

# По session_id
python dialog_trace_service.py --session-id web_123_abc

# По telegram_user_id
python dialog_trace_service.py --telegram-user-id 123456789

# Вывод в JSON формате
python dialog_trace_service.py --session-id web_123_abc --output json

# Лимит сообщений (по умолчанию 50)
python dialog_trace_service.py --session-id web_123_abc --limit 100
```

### Что показывает трассировка:

**1. Результаты микросервисов (воронка точности):**
- TagSearchService - нечеткий поиск по тегам
- SemanticSearchService - логико-семантический поиск
- VectorSearchService - семантический поиск по векторной базе
- AIAgentService - поиск с помощью YandexGPT
- Пересечение множеств (交集 - jiāojí)

**2. LLM промты:**
- Главный AI агент
- Анализатор фильтров
- Prompt Engineering данные

**3. Установленные фильтры:**
- location (Индивидуальное/Общедомовое)
- category (Водоснабжение/Отопление/и т.д.)
- incident (Инцидент/Запрос)

**4. Память диалога:**
- Контекст истории
- DialogMemoryManager состояние

**ПРАВИЛО:** Все вызовы LLM (YandexGPT, GPT и другие) должны производиться ТОЛЬКО через `AIAgentService`.

**ЗАПРЕЩЕНО:**
- Прямые HTTP запросы к API YandexGPT из других сервисов
- Дублирование кода для вызовов LLM
- Создание собственных методов `_call_yandex_gpt` в других сервисах

**КАК ПРАВИЛЬНО:**
```python
# ПРАВИЛЬНЫЙ ПРИМЕР:
class FilterDetectionService:
    def __init__(self, ai_agent_service):
        self.ai_agent = ai_agent_service

    async def detect_filters(self, message):
        prompt = self._create_prompt(message)
        # Используем AIAgentService для вызова LLM
        response, usage = await self.ai_agent._call_yandex_gpt(prompt)
        return self._parse_response(response)
```

**ПОЧЕМУ:**
1. Единая точка входа для всех LLM вызов
2. Единое логирование токенов и стоимости
3. Единая обработка ошибок
4. Нет дублирования кода

**СУЩЕСТВУЮЩИЕ СЕРВИСЫ ДЛЯ ВЫЗОВА LLM:**
- `AIAgentService` (файл: `ai_agent_service.py`) - ЕДИНСТВЕННЫЙ сервис для вызов LLM
  - Метод: `_call_yandex_gpt(prompt)` - возвращает (response_text, usage_info)
  - Логирует токены и стоимость
  - Обрабатывает ошибки API

### Запрет на использование эмодзи
**КРИТИЧЕСКИ ВАЖНО:** В проекте komunal-dom.ru категорически запрещено использовать эмодзи в коде, текстах бота и интерфейсах.

**Причины:**
- Бот должен говорить как человек, а не как робот
- Эмодзи нарушают профессиональный стиль общения
- Избегаем избыточных визуальных элементов
- Соответствие корпоративному стилю

**Правила:**
- Все тексты бота должны быть без эмодзи
- Использовать простые, понятные фразы
- Избегать избыточных рассуждений и вежливостей
- Стиль общения: прямой, деловой, по делу

**Пример ПРАВИЛЬНО:**

"Где именно это произошло?"
"Уточните детали проблемы."
